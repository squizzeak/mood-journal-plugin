# Future journal inquiries

“Next time we journal, ask me about…” creates an undated topic to retrieve at the next full session. It is not a push notification. Search active inquiry items for equivalent topics, read matches exactly, and preserve important qualifications. Create only one active item per equivalent request, using a backend reminder/note or an authorized local inquiry file.

Record a unique ID, subject, relevant user wording, request timestamp/timezone, purpose, and active status. Do not invent a deadline. A requested calendar notification requires an exposed scheduler and the user's timing; distinguish a stored due date from an actually scheduled alert. Do not silently substitute a different service. If scheduling is unavailable, say so and preserve the requested timing as pending.

Outside a journal discussion, a standalone inquiry request may be saved and verified immediately. Inside an active full or impromptu session, stage creation and status changes until explicit close; if the user explicitly requests an immediate separate action, honor that narrower instruction. Never record inquiry material from a session the user asked not to save without separate authorization.

At full-session preflight retrieve the relevant active inquiry queue, paginate and read exact matches, and retain the original wording and source date. Prioritize today's agenda. For each loaded item record a disposition at close:

- addressed: meaningfully discussed and the user indicates completion;
- deferred: keep active for later;
- retired: the user clearly no longer wants it; create a linked retirement event, preserving the original;
- not reached: keep active and report it without prolonging the session.

Mere discussion does not prove completion. If unclear, ask once whether to complete or keep the inquiry, unless the user asked to end immediately; then leave it active. Create and verify linked completion/retirement events only after the journal save is verified; never modify the original reminder's status or content. Retrieve disposition events with original reminders so completed topics are not presented as active. Include item IDs and dispositions in the journal. A failed transition remains pending. Do not create new inquiries automatically from inferred open loops or unfinished agenda items.

In single-file mode store inquiries in a dedicated section and verify the edited record. In native retained-conversation mode, record a dated inquiry/disposition in the conversation with an explicit best-effort retrieval limit. Do not call it an independently verified reminder or a guaranteed future notification.
