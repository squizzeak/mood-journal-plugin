# Contributing

Keep examples fictional and review changes for faithful source attribution, save timing, retrieval limits, and storage permissions. Run the validation and release tests listed in README.md. Add regression tests for changed release behavior and use the manual behavioral scenarios for skill changes.

Use descriptive commit subjects, optionally `feat:`, `fix:`, `docs:`, `test:`, or `build:`. All non-release commit subjects in the incremental range appear in release notes, including non-conventional subjects. Do not put private information in commits.

Changes to the skill retain CC BY-SA 4.0 and the attribution notice. This repository does not accept personal clinical records. Report a code or packaging issue with a synthetic reproduction.
